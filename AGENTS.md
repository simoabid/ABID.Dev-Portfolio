# Repository Guidelines

## Project Overview

A premium Next.js 14 portfolio website for Mohamed Amine Abid. Built with TypeScript, Tailwind CSS, GSAP + ScrollTrigger, and Lenis smooth scroll. Includes a GitHub Skills library (~60 skill files), automated image optimization pipeline (Sharp/AVIF/WebP), accessibility CI gate (axe-core), and Lighthouse CI performance enforcement.

## Project Structure & Module Organization

```
src/
  app/               # Next.js App Router pages and API routes
  components/        # React UI components (~25 files, feature-organized)
  context/           # React context providers (ThemeProvider)
  data/              # Static data (projects.ts)
  lib/               # Utilities: email, analytics, captcha, rate-limiting, scroll, validation
  styles/            # CSS design tokens (tokens.css, micro-interactions.css)
public/
  images/            # Source (raw) images
  optimized/         # Auto-generated AVIF/WebP/PNG (gitignored, generated by pipeline)
.github/
  workflows/         # CI: lint → build → a11y audit; Lighthouse CI; image optimization
  skills/            # ~60 skill directories (SKILL.md format) for AI agent guidance
  pull_request_template.md
.agent/rules/        # 11 always-on agent rules (TypeScript, frontend, design, React Native, etc.)
scripts/             # Build scripts: image optimizer (Sharp), a11y audit (axe-core/Puppeteer)
```

**Key architectural patterns:**

- `Hero` is the only statically-imported homepage section — all others use `next/dynamic` with `ssr: false` via `deferBelowFold()` in `page.tsx` so GSAP-heavy chunks stay off the server path (Lenis/global effects are deferred the same way in `layout.tsx`). Primary SEO signals come from `layout.tsx` metadata, not below-fold SSR.
- GSAP imports use `@/lib/gsap`; Lenis lives in `@/lib/scroll` and is only imported by `SmoothScrollProvider` so smooth-scroll never lands in the Hero critical bundle.
- Email provider is pluggable via `MAIL_PROVIDER` env var (Resend, SendGrid, or console-only).
- Analytics is privacy-first: GTM/GA4 loads only after explicit user consent.
- Theme is applied before React hydration via an inline `<script>` in `layout.tsx` to prevent flash of incorrect theme.

## Build, Test, and Development Commands

```bash
npm run dev           # Dev server at localhost:3000
npm run build        # Production build
npm start            # Serve production build locally

# Quality gates
npm run lint         # ESLint (next/core-web-vitals ruleset)
npx tsc --noEmit     # TypeScript strict mode check
npm run format       # Auto-format with Prettier
npm run format:check # Verify formatting without changes

# Analysis
npm run analyze      # Bundle analyzer (set ANALYZE=true before build)

# Testing & auditing
npm run test:a11y    # axe-core accessibility audit (requires running server)
node scripts/optimize-images.js --source ./public/images/raw --output ./public/optimized
```

**Single test:** `npm run test:a11y` requires a running server — start one in another terminal with `npm run dev` first.

## Coding Style & Naming Conventions

- **Linter:** ESLint with `next/core-web-vitals`; `prefer-const: warn`, `no-console: warn`
- **Formatter:** Prettier — single quotes, 2-space tabs, 80-col, trailing commas ES5, LF line endings
- **Type checking:** TypeScript `strict: true`; path alias `@/*` maps to `./src/*`
- **Component files:** PascalCase (`Hero.tsx`, `SurfaceCard.tsx`)
- **Hook files:** `use` prefix (`useScrollProgress.ts`)
- **Event handlers:** prefixed with `handle` (`handleSubmit`, `handleClick`)
- **Styling:** Tailwind-first; use `class:` syntax for conditional classes
- **Pre-commit:** Husky + lint-staged — staged JS/TS/JSX/TSX runs `eslint --fix` then `prettier --write` automatically

**Agent rules:** 11 always-on rules live in `.agent/rules/`. The most directly relevant are:

- `typescript-rules.md` — prefer interfaces over types; avoid `any`, enums, `as` assertions
- `frontend-dev-rules.md` — React/Next.js patterns; accessibility attributes required; `const` over function declarations
- `design-principles-rules.md` — WCAG 2.1 AA; mobile-first; Core Web Vitals targets

**VS Code recommended settings:** Prettier as default formatter, `editor.formatOnSave: true`, ESLint `source.fixAll` on save.

## Testing Guidelines

No unit test framework is configured. Quality assurance focuses on:

- **Accessibility:** `npm run test:a11y` runs axe-core via Puppeteer against a live server. The CI pipeline gates merges on critical/serious WCAG violations.
- **Performance:** Lighthouse CI enforces >= 90 Accessibility score on every PR. Desktop Lighthouse audits run 3 times per collect.
- **Format & types:** `npm run lint`, `npx tsc --noEmit`, and `npm run format:check` all run in CI before the build.

## Commit & Pull Request Guidelines

**Commit format:** `type` or `type(scope): description` (lowercase, no sentence-case).

Types used: `feat`, `feat(scope)`, `fix`, `fix(scope)`, `chore`, `chore(scope)`, `refactor`, `style`, `perf`, `docs`

Examples from recent history: `feat:`, `feat(polish):`, `fix(design):`, `chore(a11y):`, `chore(release):`

**PR template:** `.github/pull_request_template.md` provides the PR body structure. Fill in the summary, test plan, and any relevant notes before requesting review.
